Token 安全

Token 等同敏感憑證，不放進網址、程式、JSON、公開對話或截圖；只給最小必要權限，不需要時撤銷。

若 token 已公開

  1. 立即撤銷
  2. 建立新 token
  3. 從目前檔案移除
  4. 檢查 commit 歷史
  5. 依 GitHub 官方文件處理歷史敏感資訊

三個必看 Git 指令與安全回復

git status
git diff
git log --oneline

依序查看狀態、實際差異與版本紀錄。需要回復已發布版本時，初學者優先了解 git revert <commit-hash>：它建立反向 commit 並保留歷史。不要輕率使用 reset hard 或 force push。

快取、Console 與裝置檢查

Pages 部署需要時間，瀏覽器也可能保留舊 CSS／JS；可重新整理、無痕視窗或清除快取，不要因短暫延遲連續 push。

  • 檢查 Console error、404、圖片與 JavaScript
  • 檢查 390px、768px、桌機與鍵盤操作

日常更新流程

  1. 提出需求
  2. 限制範圍
  3. Codex 修改
  4. 檢查 diff
  5. 測試
  6. commit
  7. push
  8. 正式站驗證

Chao AI 實作所就是用一次一個明確任務、限制檔案、檢查 diff、commit 與 push，逐步加入課程、影片與 Podcast。

可複製維護指令

請對目前網站進行安全維護檢查，先不要修改。檢查 repository、branch、git status、最近 5 筆 commit、未提交變更、失效內部連結、圖片路徑、手機溢出、password／token／secret、常修改檔案與下一步順序。請區分必須立即處理、可以之後改善、不需要修改。不要建立檔案、修改、commit 或 push。

常見錯誤

  • 未確認 repository
  • 多個任務混在同一 commit
  • 未看 diff 就 push
  • token 出現在公開內容
  • 使用 force push
  • 看不到更新就重複 commit
  • 只測桌機
  • 沒有 commit message 規則
